日期：2026-09-09。运行环境：Node.js v26.8.1、npm 12.0.2、Linux、本机 SQLite 3.53.4。

## 1. 自动测试

`npm run check` 执行 TypeScript 严格类型检查、Vitest 和编译。当前共 **23 项测试通过**（5 个测试文件）。自动测试覆盖：

- YAML 受限子集、JSON Pointer 转义、Status 前置条件与 Envelope 保护；
- Git 候选结果与已发布版本分离、发布后崩溃恢复、脏工作区保护、独占锁；
- 工具结果落盘后重启，不重复执行工具，保留 reasoning 回放；
- 结束工具与其他工具混用时不部分执行，纠错上限前保全 Tool Result；
- SSE 跨字节边界、中文和分块工具参数重组，截断响应拒绝；
- HTTP Embedding 响应乱序映射、向量召回、Reranker、索引复用、修改和删除失效、历史版本隔离；
- 整份文档引用与角色知情子树求交，不注入未授权的兄弟节点；
- Orchestrator / Writer / Actor 嵌套调用、提交前逐 Status 审核及已接受结果重读；
- 跨运行保留时间预算；Antigravity 加密账号导入与原始签名片段重放。

测试使用临时 Git 仓库、可控 HTTP 响应和 Provider 替身，不使用真实账号。

## 5. 已发现并修复的问题

1. Actor 使用显示名、Orchestrator 使用 `/` 表示根 Pointer 导致协议失败：补充稳定 ID、可选根路径、清楚的 Pointer 反馈，并按响应轮而非单个工具计算纠错次数。
2. Writer 选择整份 Status，而 Actor 仅获授权其 `/status` 子树时上下文为空：改为引用范围与知情范围求交。
3. 首次生成正文后，Orchestrator 把脱外套误判为“不需要持久更新”：该结果不作为通过样本。增加必需的 reviewCandidate，以及所有 Status 的 changes / unchanged 逐项覆盖；后续真实生成已更新衣着和物体位置。
4. GitHub 推送保护拦截上游 OAuth 客户端常量：从未发布提交中移除常量，改为外部私有配置，重新执行测试与真实工具往返后推送。
5. npm tarball 不携带示例 `.gitignore`：init 显式生成故事目录的运行记录排除规则，已验证打包安装后的 doctor 不弄脏故事仓库。

失败执行和旧故事分支保留在本地证据中。逐项审核降低漏提取风险，但模型仍可能给出错误的“不变”解释；程序无法仅靠 Patch 校验保证文学事实全部正确。
